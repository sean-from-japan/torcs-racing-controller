Running it turned up one real defect: `src/run_eval.py` never cleared `sys.argv`, and
`snakeoil3_gym.Client` re-parses `sys.argv` with `getopt` when it is constructed. Every
documented flag — including `--no-nn` — therefore aborted the run before the car moved.
The original private runner cleared `sys.argv`; that line was lost in the extraction. It
is restored, with a comment saying why.

## The gym_torcs bridge

The bridge is still not redistributed. It is now *rebuilt* instead, by
`container/prepare_bridge.py`, from
[ugo-nama-kun/gym_torcs](https://github.com/ugo-nama-kun/gym_torcs) at commit
`da5d6ddec3a35718fea89dc1c05037743173c668`, with each source file verified by SHA-256
first.

Comparing the organiser's starter kit against that upstream commit settled who authored
what:

- `gym_torcs.py` in the starter kit is **byte-identical to upstream**. Every difference in
  the copy that recorded these lap times is therefore this project's own work.
- `snakeoil3_gym.py` in the starter kit *does* differ from upstream, but only inside
  `drive_example()` (a demo driver) and its `__main__` block. Neither runs on this path
  and neither is reproduced here.

The README previously said two local edits to `gym_torcs.py` were required. There are
nine, they are not all cosmetic, and the largest is that upstream gym_torcs locks the car
in first gear. That statement has been corrected in `README.md`, in `src/torcs_env.py`,
and documented in full in `container/README.md`.

## The container image

`container/image-lock.json` pins the organiser's Docker Hub image by architecture-specific
digest. The arm64 digest has been pulled and raced; the amd64 digest is recorded from the
registry and is untested here. The `latest` tag is deliberately never used — it currently
resolves to arm64 only.

The base image's build definition is not public, so this repository ships a **derived
image on a pinned base**, not a container reproducible from source end to end.
`container/Dockerfile` layers the simulator bridge and one Python dependency onto that
base; everything in it is verifiable, and CI checks that its default base digest has not
drifted from the lock. The derived image is built locally and is never pushed, which
would redistribute the organiser's image.

A from-source image was considered and deferred. The obstacle is not access to the TORCS
sources — they ship publicly in upstream gym_torcs as `vtorcs-RL-color/` with the
`scr_server` driver, and the base image carries them at `/opt/torcs-src`. The obstacle is
that a self-compiled simulator binary would not be the binary these lap times were
measured against, which would discard the baseline established here.

The organiser's starter kit, setup guides, course material and vendored TORCS sources
remain excluded; nothing from them is copied into this repository.

## Derived track data

`results/corkscrew_segments.json` and `docs/corkscrew_analysis.md` are geometric
measurements extracted by `src/analyze_track.py` from the Corkscrew track definition that
ships with TORCS (GPL-2.0). They contain no TORCS code and no track file — only numbers —
and they are kept because the s35 diagnosis is an argument from that data, not an
anecdote. Regenerate them from your own install if you would rather not take mine.
